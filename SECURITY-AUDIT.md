# Аудит безопасности (этап 2)

Метод: ручной разбор исходников и тестов, `pip-audit`, `ruff` с правилами безопасности и полный набор автоматических тестов в GitHub Actions. Проверяется код; прямой доступ к production-серверу, браузерная сессия и боевые ключи в этом аудите не использовались.

## Повторная проверка 2026-11-07

- Proxy-заголовки теперь учитываются только если TCP peer входит в `TRUSTED_PROXY_CIDRS` (по умолчанию loopback). Прямой запрос с поддельными `CF-Connecting-IP`, `X-Forwarded-For` или `X-Forwarded-Proto` не меняет IP/протокол.
- CSRF Origin проверяется по паре scheme + host, а не только по host.
- Sentry-события очищаются от `message`, `logentry`, tags, fingerprint и текста exception; стек остаётся без локальных переменных.
- Осталось проверить фактическую конфигурацию nginx: он должен перезаписывать forwarded-заголовки, а приложение должно быть доступно только через доверенный reverse proxy. Для прокси в Docker укажите его реальную подсеть в `TRUSTED_PROXY_CIDRS`.

## Проверено, замечаний нет

| Пункт | Результат |
|---|---|
| Секреты в архиве и истории | Токенов и ключей нет, `.env` в архиве пустой. В архив попали `.venv`, `donations.db`, `config.json` и `media/` (имена и сообщения зрителей, ваши файлы): в репозиторий и на сервер их не переносить, `.gitignore` это уже закрывает |

| CORS | Не включён, чужие сайты не читают ответы API (есть тест) |
| Cookie | Приложение не ставит cookie и не использует сессии, поэтому Secure, HttpOnly и SameSite не нужны |
| Форма обратной связи | В проекте её нет |
| Зависимости | `pip-audit`: известных уязвимостей нет на дату проверки. Точные версии в `requirements.lock` |

## Что осталось и о чём надо знать

| Риск | Уровень | Что делать |
|---|---|---|
| CSP для платёжной формы ЮKassa и Turnstile проверена только по документации и в имитации | Medium | При первой тестовой оплате откройте консоль браузера. Если форма не появилась, запустите с `CSP_REPORT_ONLY=1` и пришлите строки `CSP:` из лога |
| Лимиты хранятся в памяти: сбрасываются при перезапуске | Low | На этапе деплоя добавлю ограничения на уровне nginx или Caddy |
| Сервер доступен напрямую в обход Cloudflare: тогда заголовок с IP можно подделать | Medium | На этапе деплоя закрою порт файрволом, пустив только прокси |
| Basic Auth: браузер запоминает пароль | Low | Допустимо при HTTPS и HSTS. Усиление: `ADMIN_ALLOWED_CIDRS` |
| Ключ оверлея лежит в адресе (история OBS и браузера) | Low | При подозрении на утечку смените `OVERLAY_KEY` и обновите ссылку в OBS |
| Имена и сообщения зрителей хранятся в базе и копиях, а текст озвучки уходит на серверы Microsoft | Low | Храните копии закрыто. Если это неприемлемо, отключите озвучку |
| Замечания `ruff` по цепочке исключений (B904) и пустому `except` в WebSocket | Info | Стиль кода, на безопасность не влияют |
